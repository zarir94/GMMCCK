# AGENTS.md — GMMCCK

SvelteKit 2 + Svelte 5 + Vite 7 + Tailwind CSS v4 + DaisyUI v5 (`dim` default) + `adapter-node`.
Single app, no monorepo, no tests, no CI. `README.md` is a stub — trust `package.json`, configs, `src/` as source of truth.

## Hard constraints

- NEVER run any `npm run …` command (`dev` / `build` / `preview` / `check` / `check:watch` / `lint` / `format`), no `npx` verification runs, no server / preview / background processes — unless the user explicitly asks for that exact command in this session.
- NEVER `git commit` / `push` / `gh` write ops unless the user explicitly says so in this session.
- Verify by reading code, not by executing it, unless asked.

## Commands (only on explicit user request — never proactively)

- `npm run check` — `svelte-kit sync && svelte-check` (typecheck; required after `.svelte`/`.ts` edits).
- `npm run lint` — `prettier --check . && eslint .` (fails on style first; run before finishing).
- `npm run format` — `prettier --write .` (tabs, single quotes, no trailing comma, width 100).
- No test runner, no `test` script. No single-test mode exists.
- `.npmrc` has `engine-strict=true` — use `npm`, don't switch to pnpm/yarn/bun.

## Architecture

- `src/routes/+layout.svelte` — global shell: imports `./layout.css`, nav, footer, `ProgressBar`, Google Fonts (`Noto Sans Bengali`), gtag. `children` via `{@render children()}`.
- `src/routes/+page.server.ts` + `+page.svelte` — homepage: first 36 of `parsedData` + `stats_hyr.ts` / `stats_yfr.ts` result overviews.
- `src/routes/search/` — directory search: `fuzzysort` over curated keys (names/roll/phones weighted first via `scoreFn`), `PER_PAGE = 36`, pagination via `pagination-bar-generator` (`maxItemCount 7`). GET filters: `group`, `session`, `sort` + repeatable field rows (`fk`+`fv` pairs, strict per-field substring where any word may match and more matches rank first, digit-normalized for phones). Phone queries match on digits. Pagination links preserve the query via `qs`.
- `src/routes/student-[id]/` — detail page, lookup `parsedData.find(s => s.id == id)` else 404. Note hyphenated route (`/student-123`), not `/student/123`.
- `src/routes/sorry/` — cookie gate. `src/hooks.server.ts` redirects everything except `/sorry` to `/sorry` unless `allow=true` cookie. Form action sets the cookie (`maxAge` 30d). Hidden unlock: 10 rapid clicks reveal Continue.
- `src/lib/parsedData.ts` — types + default export: `data.json` sorted newest-first by `date`. Import this, never `data.json` directly.
- `src/lib/func.ts` — `CDN()` (wsrv.nl image proxy, bypasses localhost), `formatDate()`, `onImageMounted()` (removes `skeleton`), `getSubject()` (code→Bengali name map), `defaultImg`.
- `src/lib/data.json` — large static student dataset, committed to repo. Don't reformat it; `prettier --check` still covers it.
- `static/` — favicons, `robots.txt`, `site.webmanifest`. `src/lib/assets/` — `logo.png`, `og_image.jpg`, `bg_image.jpg`.

## Quirks / conventions

- Svelte 5 project but pages still use Svelte 4 idioms: `export let data` + `$:` reactives (see `+page.svelte`, `+layout.svelte`). Don't bulk-migrate to `$props()`/`$derived()` unless asked; stay consistent per file.
- Tailwind v4 CSS-first: theme/plugins declared in `src/routes/layout.css` via `@import 'tailwindcss'` + `@plugin "daisyui" { themes: dim --default; }`. That file is also `tailwindStylesheet` in `.prettierrc` — keep that pointer in sync if the CSS moves.
- `+error.svelte` is special: Tailwind classes don't apply normally there, so it uses `<style lang="postcss">@reference 'tailwindcss'; … @apply …</style>`. Copy that pattern if touching it.
- Icons: `lucide-svelte` only. Images: always route through `CDN(url, width)` + `use:onImageMounted` with `skeleton` class (see homepage cards).
- DaisyUI v5 semantic classes (`btn`, `card`, `badge-soft`, `bg-base-200`, `text-primary`, …) + `Noto Sans Bengali` base font. `frontend-design` skill taste applies: no generic purple/blue gradients, no slop.
- `tsconfig.json` extends `./.svelte-kit/tsconfig.json` (generated by `svelte-kit sync`); don't hand-edit the extended paths. `eslint.config.js` ignores via `.gitignore` (`includeIgnoreFile`).
- `vite.config.ts` sets `server.host: '0.0.0.0'` — leave it; deployment uses `adapter-node`.
